Full Editor

Batch metadata tagging for files before — or after — they join your library.

What the Full Editor is for

The Full Editor is a batch metadata-tagging workspace, built mainly as a pre-library staging tool — a place to tag a folder of freshly acquired comics (art scanned from a "Processing" folder excluded from your library scan, say) before they ever join your library, rather than something you use on issues that are already catalogued. Because it works directly against files on disk, it can also be pointed at a folder of comics that were tagged incorrectly the first time round, with no library involvement at all.

It's also useful the other way: select one or more issues already in your library and choose Send to Full Editor from the selection bar to load them in for a batch retag. That's the one case where the Full Editor does touch your library — an issue loaded this way gets an automatic rescan the moment you save it, so the corrected metadata shows up back in the library right away.

Open it from Admin → Open Editor (loads with nothing selected — you pick a folder yourself), or from a library selection's → Send to Full Editor action (skips the folder picker entirely and loads your selection straight in).

Layout at a glance

The Full Editor is the densest screen in digib00age — a four-column workspace plus a header and a footer status bar, all built to keep loading files, editing their tags, viewing pages, and queuing saves visible at the same time:

  • Column 1 — Load / Select Files: pick a folder and browse the files you've loaded.
  • Column 2 — Edit ComicInfo.xml: the actual tagging form for whichever file is currently focused.
  • Column 3 — Comic Viewer: page-by-page preview of the focused file, so you can check a cover or credits page while you tag it.
  • Column 4 — Edited Files Queue: files you've finished editing and queued up, ready to save.

The header carries two extra controls not present elsewhere in digib00age: Search ComicVine (looks up the focused file's series/issue online and can fill the form for you) and Search GoodReads (opens a GoodReads search prefilled with the focused file's Series text). A separate, optional Chrome extension can then scrape a GoodReads book page and paste its data back into the form. The footer is a status bar showing the currently selected file's name, its XML status, a running low-confidence count, and how many files are currently queued.

The four columns in detail

Column 1 — Load / Select Files

Select Folder opens digib00age's own in-app folder browser (a breadcrumb-and-tree picker, not your OS's native file dialog) — it isn't restricted to your library's root, so you can point it anywhere on the machine the server is running on. It loads only that one folder's direct contents; subfolders aren't included and there's no recursive option, so a folder full of nested series subfolders needs to be loaded one level at a time. Multi-select within a single folder is supported. Clear wipes the whole loaded set and resets the form back to empty.

Loaded files render as an expandable folder → series → issue tree, grouped by each file's nearest two directory levels. Issue rows carry an XML badge when a ComicInfo.xml is already present inside the archive, and a red-border needs-review indicator on any file flagged by an earlier low-confidence auto-tag pass (from Admin's XML Tagging or Auto Processing tools) — a visual cue for which files still need a human look. Everything is natural-sorted, so issue numbers order correctly (001 < 002 < 010) instead of alphabetically.

Clicking an issue — or moving keyboard focus onto it with the up/down arrow keys — loads its XML into Column 2 and its cover into Column 3; this is the same unified focus/load action either way. A stats line at the bottom of the column tracks Files Found, With XML, and Without XML for the currently loaded set.

Column 2 — Edit ComicInfo.xml

The same Main and More tab fields as the Basic Editor — Series Title, Issue Title, Issue Number, Year, Genre, Format, Age Rating, Black & White, Summary on Main; Count, Page Count, Writer, Penciller, Publisher, Story Arc, Language, Notes on More — with a few differences that only make sense in a batch context:

  • Increment # — a checkbox next to Issue Number. When checked, digib00age auto-increments the issue number across the loaded list in display order as you tag through it, so you don't have to type each number by hand. This is the one field with no "Apply to All" checkbox — it doesn't need one, since incrementing across files is already its whole job.
  • Apply to All — every other field gets its own checkbox in a column alongside it. Only fields whose box is checked get bulk-applied when you run Process All (below); unchecked fields keep each file's own individual value untouched. Leave everything unchecked and Process All changes nothing but what's genuinely per-file.
  • Genre is removable chips plus a ＋ Add genre dropdown, rather than the checkbox grid the Basic Editor uses — a layout better suited to a field you're likely to reuse across many files in a row.

A ＋ Queue button at the bottom adds the currently-focused file to the Edited Files Queue (Column 4) using whatever's currently in the form.

Tip

If a Writer or Penciller name you typed is a close match to someone already credited elsewhere in your library, a confirmation popup offers to use that existing spelling instead — the same near-duplicate-credit guard the Basic Editor uses. It can appear once when you click ＋ Queue, and again when you run Process All if a Writer/Penciller field is checked "Apply to All" — not per file in the queue, since each queued file's credits were already checked when it was added. It never blocks the action either way; declining just keeps what you typed.

Column 3 — Comic Viewer

A page-by-page preview of the focused file: Zoom in/Zoom out, Fit (resets to fit the frame), Prev/Next page with an "X / Y" counter, and Fullscreen. Once you've zoomed past 100%, the page becomes click-drag-pannable so you can look around it without hunting for scrollbars. A lazy page-thumbnail strip sits below the main view — thumbnails load on demand as you scroll through them, the current page is highlighted, and clicking one jumps straight to it. The cover loads automatically the moment a file is focused; every other page loads only when you actually navigate to it.

Column 4 — Edited Files Queue, and saving

Every file you've clicked ＋ Queue on shows up here as a card (a checkmark, the filename, an "Edited" tag, and a ✕ to remove it from the queue). A running "N files in queue" count sits above the cards, with a "⚠ counts differ" warning if the number of files you've loaded doesn't match the number you've queued — a quick completeness check for a batch session, so you don't accidentally save 40 of 42 files and move on.

  • Process Queue is the actual save action for queued files — there's no separate "Save" button anywhere in the Full Editor. It writes each queued file's edited XML back into its archive, and the queue empties itself automatically once processing finishes successfully.
Warning

Clear Queue abandons everything currently queued without saving any of it — none of those edits reach disk. Use it to start a batch session over, not as a way to "clean up" after a successful Process Queue (that already happens automatically).

Warning

Process All is a separate action that bypasses the queue entirely: it writes XML to every file currently loaded in Column 1 — not just the ones you've queued — applying only the fields whose "Apply to All" checkbox is ticked, batch-wide, on top of each file's own existing values. It's powerful for something like stamping the same Publisher and Genre across an entire loaded folder in one click, but double-check which boxes are actually ticked before running it, since there's no per-file preview step first.

Searching ComicVine

The Search ComicVine button in the header looks up metadata for whichever file is currently focused in Column 2, using that file's own form fields — there's no separate search box. Series is required; if it's empty, the search is blocked with a message asking you to fill it in first. Issue Number, Year, and Issue Count (if already filled in) are read along as filters to help narrow the results, but Title is not used in the search at all.

The search opens as a two-step modal:

  • Select Series — a results table (Series / Year / Issues / Publisher) with a cover preview and description. It defaults to Best Match ordering — digib00age's own fuzzy title-match-plus-issue-count ranking, not simply whatever order ComicVine happened to return — though you can re-sort by any column instead. Cancel closes the modal, Issues proceeds to the issue list for the highlighted series (same as double-clicking it), and Ok fast-paths straight past the issue list onto that series' first issue — handy for one-shots and graphic novels where there's only ever going to be one result anyway.
  • Select Issue — a natural-sorted issue list (Issue # / Date / Title) with its own cover preview and description. Click a row to preview it; double-click to confirm and apply that issue's data to the form. ← Back to Series returns to the series results you already fetched, with no re-fetch needed.
Tip

Confirming an issue match fully overwrites the mapped fields in the form — it's a replace, not a merge with whatever you'd already typed. If you've hand-edited a field you want to keep (a custom Notes entry, say), do that after confirming the ComicVine match, not before.

Search GoodReads, next to it in the header, opens goodreads.com in a new tab with a search prefilled from the focused file's Series text (if Series is empty, it opens a blank search instead). It's not wired to ComicVine or to any other form field — you still pick the right result yourself. Pairing this with the optional GoodReads Chrome extension below turns the rest of the lookup into a one-click paste instead of manual re-typing.

GoodReads Chrome extension (optional)

A small companion Chrome extension can scrape a GoodReads book page and paste Writer, Penciller, Publisher, Year, Language, Genre, and Summary straight into the focused file's form — no manual re-typing. It's a personal tool that lives outside digib00age's own codebase (a chrome-extension folder alongside the app), not something installed from the Chrome Web Store, and it's hardcoded to talk to this one digib00age instance.

Installing it

  1. Open chrome://extensions in Chrome.
  2. Turn on Developer mode (top right).
  3. Click Load unpacked and select the chrome-extension folder inside your digib00age install.
  4. A new toolbar icon appears — that's the extension.

Using it

  1. In the Full Editor, click Search GoodReads to open a search prefilled with the focused file's Series text, and pick the right book.
  2. On that GoodReads book page, click the extension's toolbar icon — it scrapes the page in the background; nothing changes visibly on the GoodReads tab itself.
  3. Switch back to the Full Editor tab. A Paste from GR button appears next to Search ComicVine/Search GoodReads, labelled with the scraped book's title. Click it to fill the form.
Tip

Genre is matched against your own current genre list (case-insensitive) — anything GoodReads lists that doesn't match (e.g. "Science Fiction" when your list has "Sci-Fi") is silently skipped rather than pasted as an invalid value; add it by hand from the Genre dropdown if you want it. Every other field is a straightforward overwrite, same "replace, not merge" behaviour as confirming a ComicVine match — if you've already hand-edited something you want to keep, do it after pasting, not before.

Warning

Each scrape is used once — pasting clears it, so a second click of Paste from GR without a fresh scrape does nothing. If you switch which file is focused between scraping and pasting, the paste still applies to whichever file is focused when you click it, so scrape and paste in one continuous pass per file.

When something needs your attention

Two modals surface only when something's actually gone sideways with a file or a batch, rather than as part of normal use:

  • If a loaded archive contains more than one ComicInfo.xml file inside it, a resolution modal shows both side by side (read-only) and asks you to pick which one to keep — the other(s) are deleted from the archive the next time that file is saved.
  • If a Process All batch save runs into trouble on some files, an error summary modal lists each failure so you can see exactly which files didn't make it through and why, without having to guess from a partial result.
